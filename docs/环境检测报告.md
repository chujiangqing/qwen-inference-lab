## 6. 显存预算怎么算（阶段 1 的参数依据）

`check_model.py` 用的模型：

```
可用显存      = VRAM_total × gpu_memory_utilization
KV 每 token  = 2 × num_hidden_layers × num_key_value_heads × head_dim × kv_dtype_bytes
               （kv_cache_dtype=fp8 时每元素 1 byte）
KV 容量       = (可用显存 − 权重 − 激活预留 1.5 GiB) / KV 每 token
是否够用      = KV 容量 ≥ max_num_seqs × max_model_len
```

以 64 层、8 个 KV 头、head_dim 128 的典型配置为例（**这是算式示例，不是本模型实测值**）：
KV 每 token = 2 × 64 × 8 × 128 × 1 = 131 072 B = 128 KiB；
`max_num_seqs=4 × max_model_len=32768 = 131 072` token 需要 16 GiB KV。
如果实测显存只有 24 GiB（0.9 → 21.6 GiB），扣掉 FP8 权重后基本放不下 4×32768，
必须下调 `max_model_len` 或 `max_num_seqs`——**这正是第 2 项待确认信息的重要性所在**。
若模型是 MLA 结构（`kv_lora_rank`/`qk_nope_head_dim`），脚本会跳过该估算并明确标注，不会给出错数。

## 7. 三个需要你拍板的决策

1. **显存与上下文**：`--max-model-len` **是双向旋钮，不只往上调**。
   - 往上调（40960）：是为了让官方工具不跳过精度评测（审计报告 P0-1）；
   - **往下调（16384）：是为了腾出 KV 换更高并发**——基线并发 4→8 吞吐不涨的真因是
     `--max-num-seqs 4` 封顶，而提到 8/16 需要 `max_model_len × max_num_seqs` 落在 KV 容量内
     （实测容量约 42.4 万 token：8×32768=26.2 万可用，16×32768=52.4 万不可用，
     16×16384=26.2 万可用）。
   - 结论：两件事分开配 profile——`baseline`(32768) 跑吞吐、`accuracy`(40960) 跑精度、
     另加缩上下文的高并发候选做对照。
2. **评测口径**：正式成绩用口径 A（官方默认，可复现）还是口径 B（复现文档原始表）？
   建议 A 为正式成绩、B 只做对照，并在报告里全程标注。
3. **MTP 默认状态**：文档显示 FP8+MTP 出现无限思考循环，需求书说第一版默认关闭。
   是否同意「默认关闭 + 单独一组 MTP 对照实验 + 把失败现象作为失败案例写入报告」。

确认这三项后，进入阶段 1（模型部署）。
